# Internasionalisasi & Lokalisasi (C12)

**Versi:** 1.0 · **Tanggal:** 2026-11-12
**Status:** Aktif. Mengikat. Menutup celah **C12** di `gaps-analysis.md`.
**Keputusan singkat:** **satu bahasa di R0 (Bahasa Indonesia), tetapi semuanya terpusat sejak hari pertama** — sehingga bahasa kedua adalah pekerjaan penerjemahan, bukan pekerjaan ulang.

---

## 1. Keputusan: satu bahasa, tapi tidak "di-hardcode"

Keputusan yang buruk ada dua, dan keduanya mahal:

| Pilihan | Akibat |
| :--- | :--- |
| **A. Hardcode teks di komponen.** | R0 cepat, lalu setiap penambahan bahasa menyentuh ratusan berkas. Biaya bahasa kedua menjadi 3–5× lipat, dan tidak pernah dikerjakan. |
| **B. Dukungan penuh i18n di R0** (banyak bahasa, penerjemahan, RTL, format per lokal). | Menyerap anggaran R0 untuk pengguna yang belum ada. `UX-B1` ikut terancam (kamus bahasa menambah bundle). |
| **C. Rekomendasi: terpusat, satu bahasa aktif.** | Semua teks lewat katalog dengan ID; hanya satu katalog yang lengkap di R0. Menambah bahasa = menambah berkas, bukan mengubah komponen. |

**Keputusan: C.**

Aturan pengikat: **tidak ada string yang tampil ke pengguna yang ditulis langsung di komponen.** Diuji otomatis (`T-I18N1`). Ini satu-satunya aturan yang membuat C bekerja.

## 2. Arsitektur string

### 2.1 Bentuk katalog

```
locales/
  id-ID/            ← lengkap (satu-satunya yang wajib di R0)
    common.json
    auth.json
    tasks.json
    teams.json
    errors.json     ← dipetakan dari `code` API
    email.json
    glossary.json
  en-US/            ← opsional; boleh tidak lengkap, dengan penanda
```

**Aturan:**

1. **ID stabil, bukan teks sumber sebagai kunci.** Kunci berupa makna: `tasks.status.changed`, bukan `"Status berubah"`. Alasan: mengganti teks sumber tidak boleh memutus terjemahan.
2. **Kunci tidak pernah didaur ulang** untuk makna berbeda. Bila makna berubah → kunci baru.
3. **Kunci yang tidak dipakai dihapus** oleh pemeriksaan otomatis (mencegah katalog membusuk).
4. **Kunci yang dipakai tapi tidak ada di katalog** = build gagal, bukan menampilkan ID mentah ke pengguna.
5. **Kamus dimuat per-rute** (code splitting), bukan satu berkas besar. Alasan: `UX-B1` — bundle awal < 300 KB gzip tidak boleh dimakan kamus.

### 2.2 Penerjemahan istilah produk (keputusan yang sering salah)

Glosarium `prd.md` §9 **adalah kontrak terjemahan**. Istilah domain **diterjemahkan**, bukan dibiarkan dalam bahasa Inggris:

| Konsep | id-ID | en-US (bila ditambahkan) |
| :--- | :--- | :--- |
| Tugas | Tugas | Task |
| Kategori | Kategori | Category |
| Goal | Goal | Goal |
| Siklus | Siklus | Cycle |
| Beban | Beban | Effort |
| Antrean | Antrean | Backlog |
| Kotak masuk | Kotak masuk | Inbox |

**Aturan:** istilah dari glosarium **tidak boleh** diterjemahkan per-layar dengan variasi berbeda. Satu istilah, satu terjemahan, di seluruh produk & dokumentasi.

**Konsekuensi untuk pencarian:** karena istilah UI bisa berbeda antar bahasa, pencarian **tidak boleh** bergantung pada label UI. Pencarian bekerja pada data & nama internal (`realtime-and-search.md` §6), bukan pada teks tombol.

## 3. Format: tanggal, angka, dan waktu

Ini sumber bug yang paling mahal dan paling sering diabaikan.

| Hal | Aturan | Alasan |
| :--- | :--- | :--- |
| **Penyimpanan waktu** | Selalu `timestamptz` UTC (`data-model.md` S5) | Satu sumber kebenaran |
| **Tanggal kalender** (due date) | `date` tanpa zona; **tidak** dikonversi | "Jatuh tempo 15 Nov" tetap 15 Nov di Jakarta & Berlin |
| **Tampilan** | Diformat di klien memakai `locale` + `timezone` pengguna | Server tidak tahu lokal pengguna |
| **Relative time** ("5 menit lalu") | Klien, dengan ambang: < 1 menit, < 1 jam, < 1 hari, lalu tanggal | Server mengirim timestamp, bukan teks relatif — teks relatif jadi salah saat halaman lama |
| **Angka** | Pemisah ribuan & desimal per lokal | `1.000` (id) vs `1,000` (en) |
| **Minggu dimulai** | Senin (id) — dapat dikonfigurasi per workspace | Kalender & siklus bergantung padanya |
| **Format tanggal absolut** | Menyertakan nama bulan, bukan angka, di tempat sempit? Tidak: tetap `dd MMM yyyy` (mis. `15 Nov 2026`) | Angka murni `11/12/2026` ambigu antara pelanggan id dan en |
| **Nama hari/bulan** | Dari lokal, bukan disimpan di DB | |
| **Zona waktu tim vs pengguna** | Batas siklus (`cycles`) memakai zona waktu **tim**, bukan pengguna | Dua orang di zona berbeda harus melihat batas siklus yang sama |

**Aturan pengikat:** **tidak ada format tanggal/angka manual** (merangkai `getDate()` + `/`) di komponen. Semua lewat satu modul format. Diuji `T-I18N3`.

## 4. Nada & tata bahasa (bukan hanya kata)

| Aspek | id-ID | Catatan untuk bahasa berikutnya |
| :--- | :--- | :--- |
| Sapaan | **Netral, tanpa "Anda"/"kamu"** sedapat mungkin ("Tugas disimpan") | Menghindari keputusan formalitas yang tidak perlu |
| Kalimat | Aktif, pendek | `onboarding.md` §8 |
| Jamak | Bahasa Indonesia hampir tidak berjamak | Katalog tetap mendukung plural (ICU) agar bahasa berikutnya tidak butuh perubahan kode |
| Gender | Tidak ada | Katalog mendukung bila perlu |
| Panjang teks | Rancang UI dengan ruang **+40%** | Teks Jerman/Inggris sering lebih panjang; tombol yang pas di id bisa terpotong |

**Aturan desain:** **tidak ada teks di dalam gambar/ikon**, dan tidak ada tombol yang lebarnya dikunci ke panjang teks satu bahasa.

## 5. Aksesibilitas & lokal

| Aturan | Alasan |
| :--- | :--- |
| `lang` pada `<html>` mengikuti lokal aktif | Pembaca layar memakai pelafalan yang benar |
| `dir="ltr"` sekarang; dukungan `rtl` **belum** (dinyatakan) | Menambahkan RTL berarti audit tata letak menyeluruh — bukan sekadar atribut |
| Kontras & ukuran font tidak bergantung pada bahasa | `NFR-015` |
| Teks tidak boleh disisipkan lewat CSS `content:` | Tidak terbaca pembaca layar & tidak bisa diterjemahkan |
| Zona waktu pengguna dapat diubah; default dari browser | Menghindari "semua jatuh tempo terlihat sehari lebih awal" |

## 6. Lokalisasi konten pengguna (batas yang dinyatakan)

| Hal | Status |
| :--- | :--- |
| Teks yang **ditulis** pengguna | Tidak diterjemahkan (memang bukan urusan kita) |
| Pencarian lintas bahasa (cari "login" menemukan "masuk") | **Tidak ada**; butuh sinonim/embedding — di luar lingkup (`realtime-and-search.md` §6) |
| Template email | Mengikuti lokal penerima; hanya id-ID di R0 (`email.md` §9) |
| Pesan error | Diterjemahkan; **`code` tidak pernah diterjemahkan** (itu kontrak mesin) |
| Format ekspor CSV | Header mengikuti lokal saat ekspor, dengan opsi "header bahasa Inggris" untuk alat lain |
| Nama status/label buatan pengguna | Tidak diterjemahkan; template tim menyediakan nama per-lokal (`FR-107`) |

## 8. Kapan bahasa kedua ditambahkan (triger, bukan tanggal)

Bahasa baru ditambahkan **hanya bila** salah satu terpenuhi:

1. ≥ 20% pengguna aktif pada instalasi nyata memakai lokal selain id-ID (terlihat dari `users.locale` — bukan asumsi), **atau**
2. Ada satu pelanggan berbayar yang mensyaratkannya, **atau**
3. Ada kontributor yang berkomitmen memelihara terjemahan (termasuk pembaruan berkelanjutan).

**Aturan yang mengikat:** **terjemahan parsial lebih buruk daripada tidak ada.** Rilis dengan katalog 60% selesai akan menampilkan campuran bahasa — itu terlihat seperti bug. Karena itu bahasa baru dirilis hanya bila katalognya ≥ 95% lengkap, dan sisanya jatuh ke id-ID dengan penanda.

**Dukungan RTL** dibuka sebagai pekerjaan tersendiri (audit tata letak, ikon, arah panah), bukan bagian dari penambahan bahasa.
